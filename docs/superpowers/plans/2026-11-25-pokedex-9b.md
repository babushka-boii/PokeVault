# Iteration 9B Collector's Pokédex implementation plan

> **For agentic workers:** execute task by task, test-first. **CLAUDE.md commit rule:** run
> the tests on their own, confirm exit code 0, and only then commit, in a separate command.
> One commit per task; never push. Stop on an unexpected failure or a new design decision. No
> code before the student approves D1–D14 in the spec (approved 2026-11-25, D2 revised).

**Goal:** a living-dex grid by generation that shows which species you own, and a species sheet
with your collection, value and every catalog card filtered by owned/missing.

**Spec:** `docs/superpowers/specs/2026-11-25-pokedex-9b-design.md`.

**Base:** `feat/iteration-9b-pokedex` from `main` `51246fc` (9A merged, PR #10).

## Global constraints

- ES/EN; code, commits and docs in English; conversation in Spanish.
- No UUID in visible or accessible content. Colours only from `tokens.css` (type colours stay
  in the allow-listed type block, used as dots).
- Owner isolation, no-store and sanitized errors on private routes. Two-user tests on SQLite
  **and** PostgreSQL.
- Never invent a count or a total; `pending` and `null` are shown honestly.
- Never read `backend/.env` or private photos. No development-database migration during the
  tasks.
- Preserve: the details endpoint, card detail, prices, favourites (optimistic ★, status batch),
  the binder and Home behaviour, and `safeReturnTo` safety.
