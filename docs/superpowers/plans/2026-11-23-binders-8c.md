# Iteration 8C binders implementation plan

> **For agentic workers:** Work test-first, one task at a time, and finish with an
> independent final review. Implementation starts only after the student approves the
> spec and this plan. Approved 2026-11-24: commit at the end of each task if tests and
> lint pass; no push; stop only on a failure, a new design decision, or at the end. The
> student applies `0007` at the end (no stop after Task 1).

**Goal:**
- Replace personal boxes with album-like binders (3×3 pages, two-page spreads, official
  card images) and a "Sin carpeta" tray.
- Store, place, move and remove copies by keyboard and touch.
- Show copy locations, migrate the boxes losslessly (`0007`), and keep the catalog boxes
  untouched.

**Architecture:**
- Backend: new `binders` and `binder_pockets` tables and a `/api/v1/binders` router that
  reuses the box patterns (owner lock, composite FKs, 404 for foreign ids, conflict
  codes).
- Prices: binder values through `PriceService`, with a grouped pass for the shelf.
- Frontend: a shelf page, a binder view, a tray, animations with reduced-motion
  fallbacks, and copy location.
- The personal-box frontend and the `/api/v1/boxes` router are retired. The box tables
  stay frozen until a later `0008` (D1).

**Stack:** the existing FastAPI, SQLAlchemy, Alembic, PostgreSQL, React and Vitest. No
new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-23-binders-8c-design.md`.

## Decisions and alternatives

Approved answers to spec §13 (D1–D8), 2026-11-24.

| Decision | Assumed | Affects |
| --- | --- | --- |
| D1 | `0007` copies boxes and keeps the box tables frozen; drop in a later `0008` | Task 1 |
| D2 | Implicit pages, cap 40 (360 pockets), one spare page shown | Tasks 1, 2, 6 |
| D3 | Only `binders.cover` (default `noir`); the sticker table is deferred to 8D | Task 1 |
| D4 | Desktop "Mis carpetas"; mobile tab "Carpetas" replaces "Cajas"; "Cajas PC" moves to Explorar | Task 5 |
| D5 | Binder ids reuse the box UUIDs | Task 1 |
| D6 | Placing a copy that is in another binder moves it atomically; responses carry `moved_from` and the status message names it | Tasks 2, 6 |
| D7 | Home previews the binder with the latest `placed_at` | Tasks 1, 8 |
| D8 | Shelf values in one `GET /prices/binders` (grouped pass) | Task 3 |

**Rejected alternatives:**
- **Drag & drop:** explicitly out of scope. The click, tap and keyboard flows cover every
  action and are testable in jsdom.
- **Storing `page_count`:** it adds a column and a UI without any user need in 8C. The
  derived spare page is enough.
- **Swapping occupied pockets:** it would hide a destructive change behind one tap. A
  409 plus an explicit move is safer, and matches today's boxes.

## Shared interfaces

**Backend:**
- `Binder` and `BinderPocket` models (spec §5).
- Schemas: `BinderSummary` (with `page_count` and `last_placed_at`), `BinderDetail` (with
  `pockets`), `CreateBinder`, `UpdateBinder`, `OrderBinders`, `PlaceInPocket`,
  `StoreResult`, `CopyLocation`.
- `next_free_pocket(session, binder) -> (page, pocket) | None`: the lowest free
  (page, pocket) up to 40×9.
- `visible_pages(max_page) -> int`: max(2, the next even number ≥ max_page + 1),
  capped at 40.
- `PriceService.values_by_group(factory, groups: Mapping[UUID, Sequence[CopyRef]],
  currency) -> list[GroupValue]`: one `_evaluate` over the union of copies, with
  per-group totals summed before rounding.

**Frontend:**
- `services/binders.ts`: `fetchBinders`, `fetchBinder`, `createBinder`, `updateBinder`,
  `reorderBinders`, `deleteBinder`, `storeNext`, `placeInPocket`, `removeFromPocket`,
  `fetchTray`, `fetchRecent`, `fetchLocations`. Each has strict validators, like
  `services/boxes.ts`.
- `services/prices.ts`: `fetchBinderValue` and `fetchBinderValues`.
- Components under `components/binders/`: `BinderShelf`, `BinderCover`, `Spread`,
  `BinderPage` (3×3 grid), `Pocket`, `SelectionPanel`, `Tray`, `MoveControls`,
  `binders.css`.
- Hook `useBinderMutations`: abort, stale-response guard, 401 → `retrySession`, 409 →
  refetch.

## Review focus

1. **Migration correctness and reversibility.**
   - Positions map exactly (p 0, 8, 9, 29).
   - Ids, names, order and timestamps are preserved.
   - Downgrade restores `0006` exactly.
2. **Isolation.**
   - No query without `user_id`.
   - Foreign ids return 404 or are absent from results.
   - Two users holding the same card never affect each other's pockets, tray, locations
     or values.
3. **Concurrency.**
   - Every write takes the owner lock.
   - Next-free is computed under the lock.
   - Occupied pockets never get overwritten or swapped.
   - Removal requires the expected copy.
4. **Failures.**
   - TCGdex or price outages never break `/inventory`, `/sets`, `/binders` or the copy
     detail.
   - Prices only disappear.
5. **Accessibility.**
   - Pocket and tray names include card, expansion, page and pocket, never a UUID.
   - Keyboard covers every action.
   - Reduced motion removes the drop and turn animations.
6. **Catalog boxes are unchanged** (`/boxes` without the mode switch). Duplicates still
   never raise completion.
