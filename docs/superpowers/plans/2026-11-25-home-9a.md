# Iteration 9A Home (final version) implementation plan

> **For agentic workers:** execute task by task, test-first. **CLAUDE.md commit rule:** run
> the tests on their own, confirm exit code 0, and only then commit, in a separate command. Never
> chain a commit after a test command. One commit per task; never push. Stop on an unexpected
> failure or a new design decision. No code before the student approves D1–D16 in the spec.

**Goal:** the final signed-in Home: greeting + value with 7-day change + scanner → "Tus
cartas" carousel (most valuable · favourites · recent) → bookshelf → Expansiones → value chart,
plus favourites, daily value records and a new-user guide.

**Spec:** `docs/superpowers/specs/2026-11-25-home-9a-design.md`.

**Base:** `feat/iteration-9a-home`, rebased on `origin/main` `84a8c30` (8D Part 1 merged,
PR #9). D1–D16 approved 2026-11-25 with D10 and D12 revised (spec §12).

**Tech stack:** existing React/TypeScript/Vite, CSS tokens, FastAPI/Pydantic,
SQLAlchemy/Alembic, PostgreSQL and SQLite tests. No new runtime dependency.

## Global constraints

- ES/EN; code, commits and docs in English; conversation in Spanish.
- No UUID in visible or accessible content.
- Colours only from `tokens.css`: gold for money, cyan for actions, and the new tokens
  `--pv-up`, `--pv-down` (AA) and `--pv-wood-*` (decorative).
- Owner isolation, session, Origin/CSRF on writes, `no-store`, and sanitized errors.
- Two-user tests on SQLite **and** PostgreSQL for every new route.
- Never invent value points.
- Never read `backend/.env` or private photos.
- No development-database migration during the tasks: commands go to the student at the end.
- Preserve existing behaviour:
  - Expansiones (`SetsProgress` with the `recent` view).
  - `GuestHome` making no private requests.
  - The valuation shared by the hero and the top cards.
  - Profile's `top=5`.
  - `InteractiveCard` and the 8D flight/menu.

### Execution notes (2026-11-25)

- Tasks 1–10 implemented, each committed after its tests, lint and typecheck passed.
- Baseline: backend 839, frontend 597. After: see the final `check.sh` run in the report.
- Deviations, all small:
  - **Name (D2):** the settings display name is not exposed to the frontend yet, so the
    greeting uses the first word of the account name; Profile will add the settings name.
  - **Star accessible name:** a fixed name "Favorita" with `aria-pressed` (the pressed state
    carries the meaning) instead of two changing names.
  - **Recording:** an empty collection records nothing, and a valuation with any copy still
    `pending` or `source_unavailable` records nothing (a lower total would be a made-up point).
  - **Home refresh:** favourites and the guide are read when Home mounts, so a star set on another page shows when returning.
  - Older migration tests no longer assume the head is `0008`.
- Mutation checks: planted bugs in the loop wrap, hover pause, the hidden duplicate, the chart
  dots, and the outside-click guard each failed tests.
